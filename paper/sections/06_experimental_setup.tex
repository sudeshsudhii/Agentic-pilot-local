\section{Experimental Setup}
\label{sec:setup}

Component studies of the gate and the router need neither a language model nor network access and were run for this paper; end-to-end runs need local models and live sites, and we specify their protocol.

\subsection{Component Studies}

\paragraph{Environment} Linux container, 4-core Intel Xeon at 2.8\,GHz, 15\,GiB RAM, no GPU; Python~3.11.15, Playwright~1.56.0 with headless Chromium~141.0.7390.37, LangGraph~1.2.12; repository commit \texttt{2361d50}. Both study scripts are in the repository under \texttt{artifacts/experiments/}.

\paragraph{Gate study} We built 35 terminal browser states in the six categories of Table~\ref{tab:gate}. Each consists of a goal, a URL, an HTML document served for that URL by Playwright request interception (no network traffic) and, where relevant, the extracted answer and the plan with step statuses, together with an oracle label $\Phi^{\star}$ and a one-line rationale. Every case ends with a dispatched action, so a dispatch-only agent reports all of them complete. The gate under test is the agent's own code: the \texttt{verify} node's CAPTCHA pre-check followed by \texttt{verify\_task\_completion}. Decisions are deterministic; latency is the median of 20 repetitions after a warm-up call. The authors wrote the cases and labels, including deliberately hard ones, so the rates describe the gate's coverage, not its expected performance.

\paragraph{Routing study} We marked a set of models as installed in the registry and called the router with the arguments used at each call site in the agent, both in isolation and in the agent's call order with the previous selection passed as the active model.

\subsection{End-to-End Protocol}

\paragraph{Hardware and models} Record CPU, GPU and VRAM, RAM, operating system, Ollama version and the digest of every model used. The default configuration uses \texttt{qwen2.5:1.5b} for text and \texttt{moondream} for vision; a second installs all configured models (Table~\ref{tab:route}). The gateway currently sends no sampling options to Ollama, so each model's default temperature applies; for reproducibility we set temperature to 0 and a fixed seed through the request options (a small code change) and run three trials per task. \todo{MEASURE: hardware, OS, Ollama version and model digests.}

\paragraph{Task suite} The benchmark list shipped in the repository has eight tasks, four of which lack a checkable success criterion. We therefore propose 30 tasks in six categories of five: navigation, search, text entry into a form, extraction of a fact with a known answer, two- to three-step tasks, and blocking or error conditions (a public CAPTCHA demonstration page, HTTP error endpoints). Each task is paired with an oracle $\Phi^{\star}$ written before any run, evaluated on the retained browser page or on the saved final screenshot and DOM snapshot by a person who does not see the agent's reported status. \todo{AUTHOR: finalize the 30 tasks and their oracles; publish them with the code.}

\paragraph{Configurations} (i)~Full system. (ii)~No completion gate: $\Phi$ replaced by ``accept'', which requires making the \texttt{verify} node honor the existing but unused \texttt{enable\_verification} flag. (iii)~No recovery: \texttt{enable\_recovery=false}, supported as is. (iv)~Vision-only grounding: the DOM manifest withheld so that every action goes through the vision model, a small change. (v)~Single model: supported as is. A memory ablation is meaningful only after the retrieval path is repaired (Section~\ref{sec:memory}); until then, (vi)~no memory is identical to (i).

\paragraph{Metrics} Task success rate under $\Phi^{\star}$; FCR (Eq.~\ref{eq:fcr}); mean number of model calls and executed actions; mean wall-clock time per task; recovery success rate (tasks that entered recovery and ended satisfied under $\Phi^{\star}$); vision-invocation rate (fraction of actions grounded by the vision model); and evidence completeness (fraction of executed actions with both screenshots, an execution record and, for completed tasks, a completion-proof screenshot). Rates are reported with Wilson 95\% intervals over task--trial pairs.
