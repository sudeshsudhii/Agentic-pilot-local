\section{Introduction}
\label{sec:intro}

Language-model agents now operate software for people: they open pages, fill in forms and read results~\cite{zhou2024webarena,he2024webvoyager,xie2024osworld}. Many send each observation, often a screenshot of a logged-in page, to a hosted multimodal model~\cite{he2024webvoyager,zheng2024seeact,zhang2025ufo}, although such screens carry names, messages and account data and personal information has been shown to leak from language models~\cite{lukas2023pii}. Independently of where the model runs, an agent can stop too early. We call this \emph{premature completion}: a terminal ``done'' while the environment does not satisfy the goal, for example after opening the search engine but before issuing the query. Each action succeeded; the task did not.

\paragraph{Research gaps} We address three gaps, each stated so that it can be tested.
\begin{enumerate}
\item[G1] \emph{In-loop completion checks are rarely measured.} Benchmarks check the final state after the episode~\cite{zhou2024webarena,xie2024osworld}, and judges assess saved trajectories~\cite{he2024webvoyager,pan2024autonomous}; when the agent itself decides, it is usually its own model that does so~\cite{yao2023react,zhang2025ufo}, and intrinsic self-correction is unreliable~\cite{huang2024cannot}. Whether a rule over observed state inside the loop withholds premature completions, and at what false-rejection cost, has not been reported with intervals and held-out data. Test: Sections~\ref{sec:method-gate} and~\ref{sec:res-gate}.
\item[G2] \emph{The contribution of each kind of evidence is unknown.} If every conjunct of such a rule contributes, removing it should raise false completions. Test: the ablation of Section~\ref{sec:res-ablation}.
\item[G3] \emph{Locality claims of local agents are rarely checked.} Running models locally is claimed to keep data on the machine, but whether an agent's process contacts other hosts is seldom measured. Test: the egress test of Section~\ref{sec:res-privacy}.
\end{enumerate}

\paragraph{Scope and terms} Agentic Pilot acts only in a Chromium browser. It is \emph{autonomous} in that, given a request, it plans and executes browser actions without step-by-step instructions; the user approves tasks classified as high-risk (posting, sending, purchasing, deleting, transferring) and solves CAPTCHAs, and no end-to-end task with a language model is evaluated in this paper. It is \emph{privacy-preserving} in a narrow sense: by default its model client sends prompts and screenshots only to a model server on the loopback interface, and it writes task records, memory and evidence only to local files (Section~\ref{sec:safety}); whether that server runs inference locally depends on its configuration. Desktop, file and process control is a design (Appendix~\ref{app:computer}).

\paragraph{Research questions} The gaps lead to five questions (Section~\ref{sec:hypotheses}): whether evidence-gated completion reduces false completions (RQ1, G1) and improves decision reliability (RQ2, G1, G2), whether memory helps repeated workflows (RQ3), whether evidence-guided recovery helps (RQ4) and what verification costs (RQ5).

\paragraph{Scientific contributions}
\begin{enumerate}
\item A formulation of evidence-gated completion that separates action dispatch from task completion, with false completion and false rejection rates (Section~\ref{sec:problem}).
\item \textsc{Actual} evidence on G1 and G2: the gate's error rates on 92 constructed states in three sets, one frozen before testing, inside the live verification node, with intervals, paired tests and a per-conjunct ablation. Rule fixes made on design states transfer only partially (Section~\ref{sec:results}).
\item A seeded, \textsc{simulation}-based evaluation of H1--H5, with inputs measured on the implementation and every assumption stated, which indicates, under those assumptions, the trade-off between false completions and false rejections and where the implementation falls short---memory without a relevance threshold, recovery blind to missing confirmations (Section~\ref{sec:sim-results}).
\end{enumerate}

\paragraph{Engineering contributions}
\begin{enumerate}
\setcounter{enumi}{3}
\item An open-source local agent with the gate inside its control loop (Algorithm~\ref{alg:loop}, Section~\ref{sec:arch}) and an implementation audit (Table~\ref{tab:status}).
\item Enforcement of a loopback-only model endpoint and an \textsc{actual} test, with a stand-in model server, that the agent's Python processes connect only to loopback addresses, addressing G3 (Sections~\ref{sec:impl} and~\ref{sec:res-privacy}).
\item An end-to-end harness: self-hosted sites with fictional content, 40 tasks with a dev/test split, an oracle validated on scripted trajectories, and baseline and ablation configurations (Section~\ref{sec:method-e2e}).
\end{enumerate}

We do not claim that the agent completes tasks: the end-to-end evaluation is implemented but not run (Section~\ref{sec:res-e2e}), and simulated results are labelled as such throughout.
