\section{Implementation}
\label{sec:impl}

The backend is Python (10{,}867 lines, 1{,}679 of them in the graph nodes) on FastAPI, LangGraph, Playwright and Pydantic, with SQLite for tasks and events and a persistent local Chroma store for vectors. The client is React in a Tauri shell; the Observatory is a separate FastAPI service with a React dashboard. The code is public at \url{https://github.com/sudeshsudhii/Agentic-pilot-local}; this paper describes commit \texttt{eb3803e}. \todo{AUTHOR: confirm license; archive the evaluated version (tagged release with DOI).}

\paragraph{Design decisions} The runner records each node's name and status in a trace and checkpoints the state after every node, so a task re-scheduled after an approval or a solved CAPTCHA re-enters the graph with its saved plan and skips intent parsing. The completion decision lives in one node; the terminal node adds a guard that downgrades a completion to \textsc{Failed} if the intent named a site but navigation was never verified. Planner output always passes through deterministic rules, which corrects small models on known patterns but places part of the behavior outside the model.

\paragraph{Evidence} Per task, the evidence directory holds before/after screenshots of each executed action, screenshots after navigation and on verified completion, the latest DOM manifest, accumulated verification and recovery records (rewritten on each update, and reset if the file fails to parse), a per-action execution record (action, URLs, screenshots, result, model, role, duration) and the node trace. A retry at the same model-call count overwrites the earlier screenshot pair, a rejected $\Phi$ evaluation keeps no page snapshot of its own, and files carry no integrity protection. Typed text is stored in clear in task events and execution records.

\paragraph{Code audit and fixes}
We traced each mechanism to the code path that executes it (Table~\ref{tab:status}) and, guided by the audit and by the gate study of Section~\ref{sec:results}, fixed the defects that stood between the code and the design. At commit \texttt{2361d50}, the extraction handler formatted every answer as facts about one university campus and substituted fixed text when a page had too few matching lines; it now keeps only page lines that share terms with the goal and invents nothing. The completion gate accepted the reasoning of any action as an answer and let a \texttt{complete} action mark a pending step done; both are fixed, and five checks were added ($Q$, the error and sign-in titles in $E$, exact matching in $T$, goal-term overlap in $X$, structured-only exemption in $R$). Bot-check detection no longer fires on titles that merely contain ``robot'' or on hidden and invisible-reCAPTCHA frames. The vision-fallback recovery strategy, memory retrieval and the verification switch were inert and now take effect, routing keywords match whole words, and stickiness no longer carries across tasks or into recovery. The evaluation command ran scripts absent from the repository and its ablation runner imported a function that did not exist; both now run the ablation presets, which gained a vision-only grounding mode and optional fixed temperature and seed. The repository's earlier ``certification'' figures counted a task as passed when it ended as completed and any screenshot and trace file existed, and we use none of them.
