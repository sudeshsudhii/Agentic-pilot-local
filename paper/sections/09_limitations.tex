\section{Limitations and Future Work}
\label{sec:limits}

\paragraph{Scope of the evidence} The completion gate is the only component measured quantitatively in this paper, and it was measured on constructed end states. End-to-end success rates, false completion rates and latencies on real sites with local models remain to be measured with the protocol of Section~\ref{sec:setup}. Latency in particular depends on the host's CPU, GPU and memory, and on which models are installed.

\paragraph{Rule-based verification} $\Phi$ is a set of hand-written checks keyed to request wording and to a few search engines. It does not compare the query in a results URL with the requested one, does not recognize soft error pages, and accepts any sufficiently long answer to an extraction request. Per-step predicates are not yet checked against the planner's stated expected outcome. We plan to derive typed predicates from the plan (as in the desktop design), to add an optional vision-model check of the final screenshot as a second opinion rather than a replacement, and to calibrate these checks against labelled trajectories.

\paragraph{Small local models} Planning quality with 1.5B--7B-parameter models is limited, and several deterministic overrides in the planner compensate for this on common patterns. Some of these overrides are site-specific. The action extraction handler also contains post-processing specific to one case-study site. \todo{AUTHOR: remove or generalize the case-study-specific extraction logic in \texttt{nodes.py} (lines 1108--1139) before any end-to-end evaluation, or disclose it explicitly here.} Canvas- and WebGL-rendered interfaces expose no useful DOM and depend entirely on the vision path.

\paragraph{Mechanisms not yet active} Strategy-specific recovery, memory retrieval, the routing cool-down and the verification ablation switch exist in code or configuration but do not affect the live path (Table~\ref{tab:status}). Activating them is a small change in each case; measuring their effect is the purpose of the ablations in Section~\ref{sec:setup}.

\paragraph{Local system and multi-agent roadmap} The local-system extension is a design. Our next steps are the path and process policy, the typed predicate library, an AT-SPI accessibility provider (testable headlessly on Linux) and the \texttt{action\_gate} node, followed by Windows UI Automation. Longer term, we intend to split planning, grounding and verification across cooperating agents, with the verifier holding no write access to the environment.
