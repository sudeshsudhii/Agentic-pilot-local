\section{Limitations and Future Work}
\label{sec:limits}

Only the gate and the router are measured here, the gate on constructed states; end-to-end rates and host-dependent latencies remain to be measured (Section~\ref{sec:setup}). $\Phi$ is keyed to request wording and a few search engines, reduces to an error check when no keyword fires, and on the live path can be satisfied by the planner's own reasoning. We plan typed step predicates derived from the planner's expected outcomes, an optional local vision-model check of the final screenshot, and calibration on labelled trajectories. Planning with 1.5B--7B models is weak, and deterministic overrides compensate on common patterns; several are site- or case-specific (the Google search rule, a click fallback that matches one site's name, substring rules that map plan steps to actions, and the extraction handler of Section~\ref{sec:impl}). \todo{AUTHOR: remove the case-specific extraction and click code (\texttt{nodes.py} lines 1052 and 1100--1142), list remaining site-specific rules in an appendix, and state whether any earlier repository figure depended on them.} Canvas- and WebGL-rendered pages depend entirely on the vision path. Strategy-specific recovery, memory retrieval, the routing cool-down and the verification switch need small fixes to take effect (Table~\ref{tab:status}). For the local-system extension we will first implement the path and process policy, the predicate library, an AT-SPI provider (testable headlessly on Linux) and the \texttt{action\_gate} node; longer term we plan to separate planning, grounding and verification into cooperating agents, with the verifier given no write access.
