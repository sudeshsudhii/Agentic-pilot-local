\section{Limitations and Future Work}
\label{sec:limits}

Only the gate and the router are measured here, the gate on constructed states; end-to-end rates and host-dependent latencies remain to be measured (Section~\ref{sec:setup}). $\Phi$ remains a set of hand-written rules keyed to request wording, a few search engines and a few error titles; it reduces to an error check when no keyword fires, and the held-out states show that fixing the rules we observed failing generalizes only partially. We plan typed step predicates derived from the planner's expected outcomes, an optional local vision-model check of the final screenshot as a second opinion, and calibration on labelled trajectories from real runs. Planning with 1.5B--7B models is weak, and deterministic overrides still compensate on common patterns, some site-specific (the Google search rule, keyword rules that map plan steps to actions). Canvas- and WebGL-rendered pages depend entirely on the vision path. Of the recovery strategies only the vision fallback changes behavior; memory retrieval now runs, but the stored records are thin and their effect on planning is unmeasured. For the local-system extension we will first implement the path and process policy, the predicate library, an AT-SPI provider (testable headlessly on Linux) and the \texttt{action\_gate} node; longer term we plan to separate planning, grounding and verification into cooperating agents, with the verifier given no write access.
