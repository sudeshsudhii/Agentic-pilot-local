\section{Security, Privacy and Ethical Considerations}
\label{sec:security}

\paragraph{Threat model} We consider (i)~instructions embedded in page content that try to redirect the agent~\cite{greshake2023indirect}; (ii)~high-impact actions such as posting, sending or purchasing without consent; (iii)~damage to the local system once file and process actions exist; and (iv)~disclosure of user data to unintended parties. The user and the host are trusted; websites are not. A compromised host or model is out of scope.

\paragraph{Current mitigations} A sanitizer replaces 17 patterns of instruction-override, delimiter, exfiltration and role-manipulation phrasing in element text, labels and placeholders before they reach the planner; retrieved knowledge is filtered the same way and marked untrusted. Before navigation, a risk gate pauses tasks whose action is posting, e-mailing, purchasing, deleting or transferring, or whose risk level is high or critical, and asks the user; the check is repeated when completion is verified. The service listens on loopback and accepts only localhost origins. Every model call is logged with destination, a locality flag and payload sizes, and credential-like values are scrubbed from broadcast events.

\paragraph{Gaps} The sanitizer is a fixed denylist; systematic evaluations find existing prompt-injection defenses insufficient~\cite{liu2024formalizing}, and paraphrased or encoded instructions do not match its patterns. The page title, URL, extracted text and screenshots are not filtered. The risk level that triggers approval comes from the same model that reads untrusted content, and one approval covers every later action of the task. The audit log covers model calls but not browsing, and a non-local model address is logged, not blocked. The privacy property we claim is therefore narrow: \emph{by default, model inference runs on the user's machine and no prompt or screenshot is sent to a model provider.} Data the user asks the agent to enter on a website still leaves the machine. The desktop design closes some of these gaps with deterministic tiers, action-bound approvals and a hash-chained audit log.

\paragraph{CAPTCHAs and automation etiquette} On a CAPTCHA or bot check the agent stops, marks the task \textsc{Blocked}, keeps the browser open, and lets the user either solve the challenge and resume, which is refused while the challenge is still present, or restart on another search engine. There is no solver. The browser is, however, launched with automation-detection features disabled, a desktop user-agent string and \texttt{navigator.webdriver} hidden, and direct loads of search-result URLs are replaced by typed queries. This is defensible for a personal assistant acting at human pace on its user's requests, but not for bulk use, and deployments should follow site terms of service. Chromium also runs with its sandbox disabled, which weakens isolation from hostile pages; re-enabling it is a simple hardening step.
