\section{Discussion}
\label{sec:discussion}

\paragraph{What the evidence supports} The gate study shows that a predicate evaluated on the observed state inside the agent loop withholds most premature completions on constructed browser states, at a cost of tens of milliseconds, and that its defects become visible only when it is tested inside the live node rather than in isolation. It does not show that the agent completes tasks, and it says nothing about desktop, file or process actions, for which no backend exists yet.

\paragraph{Why computer use raises the stakes and helps verification} Moving from the browser to the computer changes the verification problem in two directions. Desktop and file postconditions are often typed and exact, such as a content hash, a process identity or an accessibility value (Table~\ref{tab:post}), and are therefore easier to check reliably than web goals, which are defined by page content and request wording. But many local actions, such as deleting a file or closing an application with unsaved work, cannot be undone, so a postcondition checked after the action is no protection on its own. This is why the computer backend pairs postconditions with a gate that classifies and, if needed, blocks an action before it runs.

\paragraph{Rules and model judges} The held-out states show that hand-written web rules fix what they were written for and transfer poorly. Model-based judges~\cite{pan2024autonomous,sumyk2025done} cover broader goals but add inference cost and are themselves models judging models~\cite{huang2024cannot}. The two are complementary: typed, exact postconditions where the environment exposes structured state, and a judge as a second opinion where it does not, with both inputs kept as evidence.

\paragraph{Auditing an agent} Before the fixes, several advertised mechanisms (strategy-specific recovery, memory retrieval, a verification switch) had no effect, extraction substituted fixed text, and the test of the central property hung while the rest of the suite passed. A capability table that separates implemented, integrated, tested and evaluated (Table~\ref{tab:status}) was the cheapest way to find these gaps, and we recommend it as a standard part of agent papers.
