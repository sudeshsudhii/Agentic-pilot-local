\section{System Architecture}
\label{sec:arch}

\input{figures/architecture}

Fig.~\ref{fig:arch} shows the components and the trust boundary. A desktop client submits a natural-language task to a FastAPI service bound to the loopback interface. The task runner queues it, executes the agent graph, checkpoints the state after every node, and cancels tasks that exceed a wall-clock limit (5\,min by default). Checkpoints are used when a task is re-scheduled after approval or a CAPTCHA; a task interrupted by a crash is not resumed.

The agent is a compiled LangGraph state machine with eleven nodes (Fig.~\ref{fig:graph}). A typed state record carries the parsed intent, the plan and step index, the page manifest, the planned action, the action history, retry and model-call counters, routing decisions and the status; nodes return partial updates and the routers read only the status and a few flags. The single terminal node, \texttt{complete}, persists the outcome, writes memory records and decides whether the browser stays open for the user. Text-model calls go through a router (Section~\ref{sec:routing}), and all model calls through a gateway that requests JSON output from a local Ollama server, validates it against Pydantic schemas and re-prompts on malformed output. A pool of Playwright contexts over one Chromium instance, which runs with a visible window by default, gives each task its own page. Task events go to SQLite and to a broadcaster; the Observatory, a separate process, subscribes to that stream and reads the database and evidence files to display plans, routing decisions, verification outcomes and screenshots. It only issues read queries and has no command channel to the agent.

\input{figures/state_machine}

Two inputs cross into the agent: the user's task text, which is trusted, and page content, which is not. Page content reaches the models as element text, page title and URL, and, on the vision path, screenshots. Apart from one-time downloads of model weights (the Ollama models and, on first use, the default embedding model of the vector store), and, for older versions of the vector-store library, anonymous usage telemetry that the code does not disable, outbound traffic in the default configuration consists of the browser's requests to the sites a task visits; model traffic stays on the local host unless the user points the Ollama address elsewhere.
