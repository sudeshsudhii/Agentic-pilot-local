\section{Computer-Use Safety and Privacy}
\label{sec:safety}

\paragraph{Threat model} The user and the host are trusted; content the agent reads is not. We consider (i)~instructions injected through web pages, documents, file names, window titles or accessibility labels~\cite{greshake2023indirect}; (ii)~high-impact actions without consent, such as posting, sending, purchasing, deleting or overwriting files, terminating processes or changing application settings; (iii)~command execution and privilege escalation; (iv)~exposure of credentials, clipboard contents and screenshots that show sensitive data; and (v)~disclosure of user data to unintended parties. A compromised host or model is out of scope.

\paragraph{What the implementation provides} Only the browser backend acts, so threats (ii)--(iv) currently arise only through the browser; the agent exposes no file, process, window or command action. A sanitizer replaces 17 instruction-override, delimiter, exfiltration and role-manipulation patterns in element text, labels and placeholders. Before navigation, a task whose parsed action is posting, e-mailing, purchasing, deleting or transferring, or whose risk level is high or critical, waits for the user's approval; intent and risk come from the request alone, so page content cannot lower them. Bot checks stop the task for the user. The service listens on loopback, every model call is logged with destination and payload sizes, and credential-like values are scrubbed from broadcast events.

\paragraph{What it does not provide} The sanitizer is a fixed denylist, and systematic evaluations find such defenses insufficient~\cite{liu2024formalizing}; page titles, URLs, extracted text, memory records and screenshots are not filtered. The action label and risk level that trigger approval are chosen by a small model, and approval is decided once per task, so an injected instruction that steers the planner to submit a form mid-task is not gated. The API has no authentication, the audit log does not cover browsing, typed text is stored in clear, screenshots in the evidence directory are not redacted, and Chromium runs without its sandbox. We therefore make no security claim about the current system.

\paragraph{Proposed controls for the computer backend} The design of Section~\ref{sec:computer} moves the decision from the model to deterministic policy: tiers computed from the concrete action, approval bound to a hash of that action, a path jail, process launch without a shell from an allow-list with a scrubbed environment, refusal of inline interpreters and privilege elevation, reversible variants of destructive file actions (move to trash, backed-up overwrite), redaction of password fields in window screenshots, and an append-only, hash-chained log of local actions that records digests rather than file contents or typed text. A design in the spirit of CaMeL~\cite{debenedetti2025camel}, in which untrusted content cannot change the control flow, is a stronger alternative that we have not explored. None of these controls is implemented, and their effectiveness must be measured on safety tasks such as those of OS-Harm~\cite{kuntz2025osharm}.

\paragraph{Privacy and etiquette} We call the system privacy-preserving in a specific sense: \emph{by default, model inference runs on the user's machine, no prompt or screenshot is sent to a model provider, and task records, memory and evidence are stored only on the local disk}. This is a default, not an enforced guarantee: the model address is configurable, and a non-local address is logged but not blocked. Locally stored data is not encrypted, data the user asks the agent to enter on a website reaches that website, and model weights and, for some library versions, vector-store telemetry are fetched or sent unless disabled. The browser hides common automation signals and types search queries rather than loading result URLs; we consider this acceptable only for a personal assistant acting at human pace on its user's requests, and deployments should disable it where a site's terms prohibit automated access.
