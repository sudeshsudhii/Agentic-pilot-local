\section{Results}
\label{sec:results}

All results concern the browser backend and its components.

\subsection{Completion Gate (G1)}
\label{sec:res-gate}

\input{tables/gate_results}

Table~\ref{tab:gate} reports the gate study. On the code before the fixes, the pre-check and $\Phi$ withheld 15 of the 23 unsatisfied design states and rejected 3 of the 15 satisfied ones; inside the live verification node they withheld only 14 (empty planner reasoning) or 13 (verbose reasoning), because the node let a premature \texttt{complete} mark a pending step done and took the planner's reasoning for an answer. After the fixes all three modes agree on every state of every set. On the design states the gate withholds 20 of 23 and rejects 1 of 15, and corrects 7 states relative to the earlier gate without breaking any; we report these counts without significance tests, because the fixes were designed on these states and a test of them would be circular.

The held-out sets give a less optimistic estimate. On held-out~2, frozen before testing, the gate withholds 9 of 22 unsatisfied states (0.41; 95\% interval 0.23--0.61) and rejects 1 of 20 satisfied ones (0.05; 0.01--0.24), so it is correct alone on 9 states and wrong alone on 1 (exact McNemar $p=0.021$); pooled with held-out~1, it withholds 11 of 27 (0.25--0.59) and rejects 2 of 27 (0.02--0.23; 11 against 2, $p=0.022$). On held-out~1 alone (2 against 1; $p=1.0$) the smallest attainable $p$ with three discordant states is 0.25, so the test cannot show a difference. Its misses follow from the rules: the answer check $X$ fires only on words such as ``extract'', so requests phrased ``tell me'' or ``what year'' are not checked, and when it fires it accepts any answer that repeats a goal term; none of the 5 unsatisfied extraction states is withheld. Unparsed text-entry phrasings, unfamiliar error titles and an add-to-cart click that added nothing also pass; the one false rejection is a page that merely mentions reCAPTCHA. Hand-written rules thus fix the cases they were written for and generalize only partially, which answers G1 with a qualified yes: the gate is correct on significantly more held-out states than a dispatch-only rule and withholds 41\% of premature completions, with a false-rejection rate whose 95\% upper bound is 0.24, but far fewer than on the states it was designed on. Against the stronger baseline of the measured basic detector that applies only the error check $E$, which withholds 2 of 22 and rejects none, the gate is correct alone on 7 held-out-2 states and wrong alone on 1 ($p=0.070$; pooled 8 against 2, $p=0.11$): on new phrasings, the evidence that the conjuncts beyond $E$ add decision accuracy is suggestive but not significant.

\subsection{Contribution of Each Conjunct (G2)}
\label{sec:res-ablation}

Removing one conjunct at a time (Supplement, Table~\ref{tab:ablation}) raises false completions on the design states, most for the error check $E$ (3$\to$8) and the search-home check $H$ (3$\to$7), but changes at most three held-out decisions, and removing $Q$ or $X$ changes none: these checks rarely fire on phrasings they were not written for, so the gate's coverage, not the strength of any single check, limits it.

\subsection{Overhead}
\label{sec:res-overhead}

$\Phi$ makes no model call and no browser action; it reads the page through the browser protocol. Over the 83 decisions that evaluate $\Phi$ the median latency was 26.8\,ms (90th percentile 29.5\,ms, 95th 30.3\,ms, maximum 34.6\,ms; percentiles of per-state medians of 20 repetitions, which understate the tail of single decisions), and decisions stopped by the pre-check took at most 13.4\,ms. Its added tokens and API cost are zero; the added steps that a rejection causes can only be measured end to end (Section~\ref{sec:res-e2e}).

\subsection{Locality (G3) and Oracle Validity}
\label{sec:res-privacy}

We ran 70 agent episodes (10 development tasks under 7 configurations, six with memory) through the real control loop and Chromium against the local sites, with a scripted stand-in for the Ollama API on 127.0.0.1, on the clean commit \texttt{7133301}, whose agent code is that of \texttt{bf0a8a5}; an earlier run on an uncommitted tree gave the same result, and both raw logs are released. Every \texttt{socket.connect} and \texttt{connect\_ex} call in the harness's eight Python processes was logged; UDP, DNS lookups, native-code sockets, the Playwright driver, Chromium and the model server were not instrumented. All 555 attempts went to the stand-in on 127.0.0.1, and every page request Playwright reported named host 127.0.0.1. Because the stand-in claims completion at once, the episodes made no browser action after the first navigation and never called the vision model; memory retrieval returned records in 54 of the 60 memory-enabled episodes. The test suite runs a reduced version of this check, which asserts loopback hosts but not the port, with tests that a remote model address is refused and Chroma telemetry is off; 144 of 147 tests pass (2026-10-04; the 3 failures need live websites or a model).

The end-to-end oracle agreed with the intended verdict on all 114 scripted trajectories. The informative cases are 35 correct solutions (no false negative; 95\% interval 0--0.10) and 34 near misses (no false positive; 0--0.10); the rest are negative by construction. This bounds errors on anticipated behaviors only.

\subsection{Scope of the Measurements}
\label{sec:res-e2e}

These measurements characterize the gate, browser and memory components, locality and the oracle under controlled conditions. Task success of the full agent and the task-level effects of the gate, memory and recovery are examined in simulation (Section~\ref{sec:sim-results}); the released harness supports their direct measurement.
